# TASKS: Freelance CRM

> Связанный документ: [PRD.ru.md](PRD.ru.md) · Процесс: TDD (red → green → refactor)

## Как работать с этим файлом

- Каждая задача имеет ID `T-<milestone>.<n>`, ссылки на требования PRD (`FR-…`), зависимости и раздел **Тесты (red)** — они пишутся **до** реализации и должны сначала упасть.
- **Definition of Done** для любой задачи:
  1. тесты из раздела «Тесты» написаны первыми и теперь зелёные;
  2. `cargo clippy -D warnings`, `cargo fmt --check`, `pnpm lint`, `pnpm check` проходят;
  3. покрытие не ниже порога (NFR-6);
  4. все новые строки UI есть в `messages/en.json` и `messages/ru.json`;
  5. CI зелёный на Linux, Windows и macOS.
- Статусы: `[ ]` — не начато, `[~]` — в работе, `[x]` — готово.
- Каждый milestone завершается работающим инкрементом приложения.

## M4. Vault (секреты)

- [ ] **T-4.1 Крипто-примитивы** (PRD §6.4)
  - `derive_kek(password, salt, params)`, `wrap` и `unwrap` DEK, `seal` и `open` (XChaCha20-Poly1305 с AAD).
  - **Тесты:**
    - round-trip;
    - неверный пароль даёт `vault.wrong_password`;
    - изменённый шифротекст, nonce или AAD — ошибка;
    - nonce уникален (10 000 вызовов);
    - тест-векторы Argon2id из RFC 9106;
    - proptest round-trip на случайных данных;
    - ключевые типы реализуют `Zeroize` (проверка на уровне типов).

- [ ] **T-4.2 Состояние Vault** (FR-VA-1, 2, 10)
  - `VaultService`: `init`, `unlock`, `lock`, `change_password`, `status`.
  - **Тесты:**
    - автомат состояний (`uninitialized` → `unlocked` → `locked` → `unlocked`);
    - `init` при существующем vault — ошибка;
    - после `change_password` старый пароль не подходит, новый подходит, ранее зашифрованные секреты читаются;
    - операции над секретами в `locked` дают `vault.locked`.

- [ ] **T-4.3 Автоблокировка** (FR-VA-3)
  - Таймер бездействия (часы инжектятся через трейт `Clock`); события активности приходят с фронтенда; блокировка при сне или lock экрана (best effort по платформам).
  - **Тесты:**
    - с fake clock блокировка происходит ровно после таймаута;
    - активность сбрасывает таймер;
    - таймаут 0 означает «никогда».

- [ ] **T-4.4 Модель секретов и шаблоны типов** (FR-VA-4, 5)
  - Enum `SecretKind` и схема полей каждого шаблона (поле обязательное или нет, секретное или нет, многострочное или нет); payload хранится в JSON и шифруется.
  - **Тесты:**
    - каждый шаблон валидирует обязательные поля;
    - в БД нет открытого текста: тест пишет секрет с маркером `PLAINTEXT_MARKER_42` и сканирует байты файла БД и WAL;
    - заголовок секрета попадает в FTS, значения полей — нет.

- [ ] **T-4.5 Сервис и команды секретов**
  - Команды list (без значений), `reveal_field(id, field)`, create, update, delete, `copy_to_clipboard(id, field)`.
  - Значение копируется в буфер на backend, без передачи во фронтенд.
  - **Тесты:**
    - list не содержит зашифрованных полей;
    - `reveal` в `locked` даёт ошибку;
    - `copy_to_clipboard` вызывает плагин (мок).

- [ ] **T-4.6 Генератор паролей** (FR-VA-7)
  - **Тесты:**
    - длина соблюдается;
    - каждый выбранный набор символов присутствует хотя бы раз;
    - исключённые похожие символы не появляются (proptest);
    - расчёт энтропии;
    - passphrase использует словарь, количество слов и разделитель соблюдаются.

- [ ] **T-4.7 Генератор и импорт SSH-ключей** (FR-VA-8, 9)
  - **Тесты:**
    - Ed25519 и RSA-4096 генерируются, публичный ключ соответствует приватному;
    - ключ с passphrase расшифровывается только с ней;
    - импорт OpenSSH-ключа определяет тип и комментарий;
    - экспорт на Unix создаёт файл с правами `0600`;

- [ ] **T-4.11 Ключ восстановления** (FR-VA-11; PRD §6.4 п. 8)
  - Генерация RK при `init`, кодирование base32 по группам с контрольной суммой, `recover(rk, new_password)`, `rotate_recovery_key()`.

    - ввод нечувствителен к регистру, пробелам и дефисам;

    - экран показа ключа с кнопками «Сохранить в файл» и «Печать»;
    - шаг подтверждения просит ввести 2 случайные группы, при ошибке не пускает дальше;
    - ссылка «Забыли пароль?» на lock screen ведёт в форму ввода RK и нового пароля.

## M5. Файлы и изображения

- [ ] **T-5.1 Content-addressed хранилище** (FR-FI-2, 6, 7)
  - `BlobStore::put(reader) -> BlobId` (потоково, SHA-256, layout `ab/cd/<hash>`), `get`, `delete_if_unreferenced`.

    - превышение лимита размера даёт ошибку, временный файл удалён;

- [ ] **T-5.2 Шифрованные блобы** (FR-FI-5)
  - STREAM-шифрование чанками; для шифрованных блобов content-addressing не применяется (случайный id).
  - **Тесты:**
    - round-trip для 0 байт, 1 байта, ровно 64 КБ, 64 КБ + 1 байт и 10 МБ;
    - перестановка или удаление чанка обнаруживается;
    - открытый текст отсутствует на диске;
    - в `locked` — ошибка.

- [ ] **T-5.3 Вложения (полиморфные)** (FR-FI-1)
  - **Тесты:**
    - прикрепить к каждому типу владельца;
    - удаление владельца удаляет вложения и освобождает блобы;
    - вложения секретов всегда шифруются.

- [ ] **T-5.4 Миниатюры изображений** (FR-FI-3)
  - **Тесты:**
    - PNG, JPEG и WebP дают миниатюру не больше 320 px с сохранением пропорций;
    - EXIF-ориентация учитывается;
    - для не-изображения миниатюры нет и ошибки нет;
    - для шифрованных изображений миниатюра тоже шифруется.

- [ ] **T-5.5 Открытие и экспорт** (FR-FI-4)
  - Открытие системным приложением, «показать в папке», «сохранить как».

  - **Тесты:**

- [ ] **T-5.6 UI: вложения**

## M9. Финансы

- [ ] **T-9.1 Счета: модель и расчёт** (FR-FN-1, 2, 3)
  - **Тесты (100% веток):**
    - сумма позиций, скидка (% и фиксированная), налог;
    - округление half-even в минимальных единицах;
    - валюта с 0 знаков (JPY) и с 3 знаками (KWD);
    - запрет смешения валют позиций;
    - вычисляемый статус `overdue` на фиксированном `now`;
    - `partially_paid` и `paid` по сумме платежей.
    - клиента со счетами удалить нельзя (`client.has_invoices`), `DeleteImpact` показывает счета (перенесено из T-1.12).

- [ ] **T-9.2 Нумерация счетов** (FR-FN-3)
  - **Тесты:**
    - шаблон `INV-{YYYY}-{NNN}`;
    - счётчик сбрасывается в новом году;
    - уникальность при конкурентном создании (транзакция);
    - ручной номер проверяется на уникальность.

- [ ] **T-9.3 Счёт из записей времени** (FR-FN-4, FR-TT-5)
  - **Тесты:**
    - берутся только billable и неинвойснутые записи за период;
    - группировка по задаче и одной строкой;
    - записи помечаются `invoice_id`;
    - отмена счёта (`cancelled`) освобождает записи.

- [ ] **T-9.4 Платежи** (FR-FN-6)
  - **Тесты:**
    - частичная оплата;
    - переплата даёт предупреждение;
    - удаление платежа пересчитывает статус;
    - платёж без счёта учитывается в доходе проекта.

- [ ] **T-9.5 Расходы** (FR-FN-7)
  - **Тесты:** CRUD; категории; прикрепление чека (через M5); прибыль проекта равна оплаченному минус расходы (по валютам).

- [ ] **T-9.6 PDF счёта** (FR-FN-5, FR-CO-3; по итогам T-0.9)
  - Шаблоны `international` и `ru_invoice` («Счёт на оплату»: банковские реквизиты, «Без НДС», сумма прописью); выбор по стране исполнителя; снимок реквизитов в счёте; логотип.
  - **Тесты:**
    - сумма прописью на русском (рубли и копейки, склонения: 1 рубль, 2 рубля, 5 рублей; 11–14; ноль; миллионы) — табличные тесты;
    - формулировка «Без НДС» для НПД и УСН;
    - снимок реквизитов: правка профиля после выставления не меняет PDF старого счёта;
    - PDF валиден, содержит номер, суммы и кириллицу (извлечение текста);
    - язык счёта влияет на подписи;
    - snapshot текстового слоя;
    - отсутствие логотипа не ломает рендер;
    - подпись и печать выводятся только при включённой опции; переопределение в счёте имеет приоритет над настройкой профиля.

- [ ] **T-9.12 Налоги** (FR-FN-10)
  - Налоговые режимы (пресеты из схем стран и «Свой»), правила «ставка + условие», расчёт налога от платежей.
  - **Тесты (100% веток):**
    - НПД: платёж от клиента-физлица — 4%, от организации или ИП — 6%;
    - УСН 6% с редактируемой ставкой;
    - «Свой» режим;
    - выключенные налоги дают отсутствие налоговых полей в агрегатах (не ноль);
    - налог считается по дате платежа в таймзоне пользователя;
    - округление в минимальных единицах;
    - мультивалютность (налог отдельно по каждой валюте);
    - смена режима в середине года не пересчитывает задним числом (режим действует с даты).
  - **Тесты UI:** переключатель «учитывать налоги»; выбор пресета страны; редактор правил.

- [ ] **T-9.7 Дашборд: агрегаты** (FR-FN-8)
  - **Тесты:**
    - при включённых налогах — налог и чистый доход за период;

    - неоплаченные и просроченные;
    - пустой период даёт нули, а не ошибку.

- [ ] **T-9.8 UI: счета**

  - **Тесты:** переключатель валюты; график получает корректные серии; клик по клиенту ведёт в его финансы.

- [ ] **T-9.10 Срок оплаты в календаре** (FR-FN-9) — S

## M11. Бэкап и восстановление

- [ ] **T-11.1 Экспорт бэкапа** (FR-BK-1, 4)
  - `VACUUM INTO` → zip (БД, блобы, `manifest.json` с версией схемы и хэшами) → age (passphrase).
  - **Тесты:**
    - архив расшифровывается только верным паролем;
    - manifest корректен;
    - секреты внутри остаются зашифрованными (маркер-тест);
    - бэкап во время записи в БД консистентен.

- [ ] **T-11.2 Восстановление** (FR-BK-3)
  - **Тесты:**
    - round-trip: полный набор данных (фикстура-генератор) → backup → restore в пустую папку → данные идентичны (сравнение дампов);
    - битый архив или неверный пароль не меняют текущие данные;
    - бэкап от более новой версии схемы даёт ошибку;
    - бэкап от старой версии мигрируется;
    - перед заменой создаётся автобэкап.

- [ ] **T-11.3 Автобэкап по расписанию и ротация** (FR-BK-2)
  - Пароль хранится в OS keychain (`keyring` crate) или используется ключ Vault.
  - **Тесты:**
    - планировщик с fake clock делает бэкап по расписанию;
    - ротация оставляет N последних;
    - недоступная папка даёт уведомление об ошибке без падения.

- [ ] **T-11.4 Экспорт JSON и CSV** (FR-BK-5) — S
  - **Тесты:** snapshot JSON-структуры; CSV для клиентов, проектов, задач и времени; секреты не экспортируются.

- [ ] **T-11.5 UI: бэкап**

## Порядок и зависимости (кратко)

```
M0 ─┬─ M1 ── M2 ── M3 ─┬─ M6 ── M7 ── M9 ─┐
    │                  │                  ├─ M10 ── M11 ── M12
```
